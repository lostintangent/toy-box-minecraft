# assets-src: Toy Box art pipeline

Deterministic generators for every Toy Box block texture, model and GUI sprite. Style: "Toy Box"
(docs/visual-bar.md). Agent skins and portraits are not generated here: the mod draws them at runtime
from each member's avatar (`AvatarArt`). This README is generated by `gen/readme.py`; the manifest
below is read from the real `out/` tree.

## Regenerate

```sh
# one-time: project venv (no global installs)
python3 -m venv assets-src/.venv
assets-src/.venv/bin/python -m pip install -r assets-src/requirements.txt

assets-src/.venv/bin/python assets-src/build.py            # all shipped assets, a few seconds
assets-src/.venv/bin/python assets-src/build.py --verify   # rebuild in 2 fresh processes (PYTHONHASHSEED 1, 987654), assert byte-identical
```

`requirements.txt` pins Pillow (11.3.0): PNG bytes depend on the Pillow/zlib build, and `sync.py --check` compares bytes.
`out/` is build output and is not committed; the synced copy in `mod/` is.

Single steps: `python gen/blocks.py`, `gen/models.py`, `gen/gui.py`, `gen/ui_style.py`, `gen/brand.py`.

## Sync into the mod

```sh
python assets-src/sync.py --dry-run   # what would change
python assets-src/sync.py             # copy out/assets -> mod/src/main/resources/assets
python assets-src/sync.py --check     # exit 1 if the mod copy is stale (use before a build)
```

`sync.py` is stdlib-only. It never deletes files it did not put there (ledger:
`mod/src/main/resources/assets/toybox_minecraft/.art-sync.json`), so mod-owned files such as `icon.png` are safe.

**Lang files are merged, not copied.** Minecraft loads one `lang/<locale>.json` per namespace per pack, so the
mod's own keys (keybinds, screen titles, messages) and the generated block/item names share
`assets/toybox_minecraft/lang/en_us.json`. Edit that file in `mod/` as usual: sync owns only the keys it generates
(`block.toybox_minecraft.*`, `item.toybox_minecraft.*`, `itemGroup.toybox_minecraft`), updates them in place, removes ones
assets-src stopped generating, and keeps every other key verbatim in the file's order (a mod value for a
generated key is overwritten with a warning). `--check` compares the merged result by content, so mod-added keys
or CRLF line endings never count as stale.

## Palette

`palette.json` holds every colour value the shipping generators use (named colours, material ramps, status
ramps, UI and toy colours). Generators reference entries by name (`pc("ramps.brass[2]")`); `gen/validate.py`
fails the build if a quoted hex literal appears in any shipping generator. Generators may still blend two palette
entries (`mix`) for glints and falloffs, so not every shipped pixel colour is listed: the build prints the split.
The mod reads the shipped copy for UI colours (`UiStyle`).

## Block contract (what the Java side must declare)

`facing` = direction the front faces = towards the placing player (`ctx.getHorizontalPlayerFacing().getOpposite()`),
like vanilla lecterns/furnaces. Emissive parts follow vanilla `cross_emissive`: an exact duplicate element with
`"light_emission": 15` and `"shade_direction_override": "up"` (26.3 no longer parses the old `"shade": false`),
and every model with one sets `"ambientocclusion": false`. **Render layers are automatic in 26.3**: each quad
goes to SOLID / CUTOUT / TRANSLUCENT from the alpha of the texture region it samples
(`ChunkSectionLayer.byTransparency`), so no `BlockRenderLayerMap` call is needed; the column below says where
the quads end up. Non-cube shapes still need `noOcclusion()`. Suggested luminance is for the block's light level
(separate from the full-bright faces).

## GUI kit

Sprites live in the vanilla GUI sprite atlas: `assets/toybox_minecraft/textures/gui/sprites/kit/<name>.png`. Draw them
with the Minecraft 26.3 (Mojang-named) API:

```java
// graphics: net.minecraft.client.gui.GuiGraphicsExtractor
graphics.blitSprite(RenderPipelines.GUI_TEXTURED,
        Identifier.fromNamespaceAndPath("toybox_minecraft", "kit/panel_paper"), x, y, w, h);
```

21 of the 39 sprites are stretchable and ship a `.png.mcmeta` with `gui.scaling` nine_slice insets, so
vanilla nine-slices them; the other 18 (icons, dots, bubble tail, checkboxes) are
fixed-size and drawn at their own size. 1 texel = 1 GUI px. Full manifest with content padding and text colours:
`assets/toybox_minecraft/gui/kit.json`. Colour/typography rules: `ui-style.md`.
